# ADR-0002: frontend / backend のモノレポ構成にする

- ステータス: Accepted
- 日付: 2026-10-30

## コンテキスト

run-buddy は Web UI（ダッシュボード、Plan入力）と REST API（Garmin連携、AI相談、スプレッドシート連携）からできています。
開発者は1人（＋AI エージェント）なので、API の変更と UI の変更を一緒にレビュー・コミットできる方が楽です。

## 決定

1つのリポジトリの中を、次のトップレベルディレクトリに分ける。

```
backend/   Spring Boot（Maven プロジェクトとして単体でビルドできる）
frontend/  Web UI（Node プロジェクトとして単体でビルドできる）
docs/      コンセプト・ADR
```

- それぞれのディレクトリの中で、そのエコシステムの標準ツールでビルド・テストが完結するようにする（ルートに全体をまとめるビルドツールは今は入れない）。
- frontend と backend の契約は REST API とし、将来は OpenAPI でスキーマを共有する（別の ADR で決める）。

## 検討した選択肢

| 選択肢 | 判断 |
|---|---|
| リポジトリを分ける（frontend / backend） | 1人開発では、API 変更のたびに2つのリポジトリをそろえる手間の方が大きい |
| モノレポ + Nx / Turborepo などのツール | 言語が2つしかなく、今は過剰。必要になったら検討する |
| **シンプルなモノレポ（ディレクトリで分けるだけ）** | 採用 |

## 結果（トレードオフ）

- 良い点: 1つの PR で API と UI をまとめて変更できる。AI エージェントが全体を見渡しやすい。
- 注意点: CI では変更のあったディレクトリだけを対象にする工夫（パスフィルタなど）が必要になる。
