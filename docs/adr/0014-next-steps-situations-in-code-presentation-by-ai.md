# ADR-0014: ダッシュボードの「いまやること」は、状況の判定をコードで、見せ方を AI でする

- ステータス: Accepted
- 日付: 2026-11-06
- 関連: #26（親）、#27（ステップ1）、#28（ステップ2）、#29（ステップ3）、ADR-0008（AI 相談）

## コンテキスト

ダッシュボードを開いたとき、いまやるべきこと（目標からの遅れを取り戻す、次月の計画を作る、レース前に量を落とす、など）を一番上に出したい。「状況に応じて画面を変える」ことを AI に任せる案（Generative UI）がある。

AI に画面（HTML や JSX）そのものを作らせると、テストできず、壊れた画面や事実と違う数字も出せてしまう。

## 決定

1. **状況（`Situation`）の判定はドメインのコードでする。** `dashboard/SituationRules` が `TrainingSnapshot`（今日、今月の計画と実績、次月の計画の有無、レース、最後のランの日）から、状況を決定的に判定し、急ぐ順に並べる。「今日」は引数で受け取り、時計に依存しない。
   - `RaceApproaching`：レースまで 21 日以内（当日を含む）。アドバイザーのテーパリング（最後の 2〜3 週）に合わせる。
   - `BehindTarget`：経過日数の割に、目標の 1 割以上足りない。**レースが近いあいだは出さない**（量を落とすのが計画どおりなので）。
   - `NoRunsLately`：7 日以上走っていない。最初の取り込みの前は出さない。
   - `MonthEnding`：月末まで 7 日以内で、次月の計画（目標かワークアウト）がない。
   - 並びは `RaceApproaching` → `BehindTarget` → `NoRunsLately` → `MonthEnding`（`SituationRules.ORDER` の1か所）。
2. **API は「カードの種類と数値」だけを返す。** `GET /api/next-steps` の `cards` は `kind` で区別するユニオン型（OpenAPI の `oneOf`、TypeScript では判別可能なユニオン）。文言は frontend（`lib/nextSteps.ts`）が持つ。
3. **カードは画面を開くだけで、何も保存しない。** AI 相談は `/advisor?ask=...` で入力欄に依頼を入れた状態で開き、送るのは人。次月の計画はプラン画面を開く。
4. **見せ方（どのカードを、どの順で、何と書くか）を AI に任せるのはステップ2（#28）。** AI の応答は信用しない入力として検査し、失敗したらこの ADR のルールの並びで出す。

## 検討した選択肢

| 案 | 判断 |
|---|---|
| A. AI に画面を生成させる | テストできない。数字の誤りや壊れた画面を防げない |
| **B. 判定はコード、見せ方は決められたカードの中から AI が選ぶ**（採用） | 判定は単体テストで守れる。AI が失敗しても、ルールの並びで同じ画面が出る |
| C. ルールだけ（AI なし） | ステップ1はこれ。AI らしい優先順位や言い回しは出ない |

## 結果

- 良い点：判定は境界値まで単体テストで守る（`SituationRulesTest`）。カードの数値は API の `@WebMvcTest`、文言と行き先は Vitest で守る。
- 良い点：カードの種類が増えても、`Situation` の sealed interface と `switch` の網羅性チェック（Java）、判別可能なユニオンの網羅性チェック（TypeScript）が、直す場所を教えてくれる。
- 注意点：しきい値（21 日、1 割、7 日、7 日）は経験則。使いながら見直す。
- 注意点：カードは「今日」のこと。ダッシュボードで今月を見ているときだけ出す。
