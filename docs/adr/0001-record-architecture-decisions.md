# ADR-0001: ADRで設計判断を記録する

- ステータス: Accepted
- 日付: 2026-10-30

## コンテキスト

run-buddy は Claude Code などの AI エージェントと一緒に開発を進めます。
人間にとってもエージェントにとっても、「なぜこの設計にしたか」がリポジトリの中に残っていないと、
同じ議論を何度もしたり、前提を外した変更をしてしまったりします。
また、将来は `docs/` を入力にしてWikiを自動生成したいと考えています。

## 決定

- 重要な設計判断は `docs/adr/NNNN-kebab-case-title.md` に、Michael Nygard 形式をもとにした ADR として残す。
- ステータスは `Proposed` → `Accepted` →（必要なら）`Deprecated` / `Superseded by ADR-XXXX` と進める。
- Accepted になった ADR の本文は書き換えない。判断を変えるときは新しい ADR を作り、古い方を Superseded にする。
- 図は Mermaid で書く（テキストなので差分が見やすく、自動ドキュメント生成ツールでも扱いやすい）。

## 結果（トレードオフ）

- 良い点: 判断の理由がコードの隣に残る。AI エージェントにも前提として読ませやすい。
- 注意点: 書くための手間がかかる。小さな判断まで ADR にしないようにする。
