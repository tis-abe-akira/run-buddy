# ADR-0010: クラウドに公開せず、手元のマシンで動かして Tailscale でつなぐ

- ステータス: Accepted
- 日付: 2026-10-31

## コンテキスト

run-buddy を別の端末やスマホからも使いたい。ただし、次の制約がある。

- **ログイン機能がない**（全員が `runbuddy.default-user-id` のユーザーとして扱われる）。インターネットに公開すると、誰でも Garmin の記録（心拍数などの健康データ）を見られ、オーナーの API キーで Garmin の取り込みや AI 相談を実行できてしまう。
- 使うのは今のところオーナー一人。
- 費用はかけたくない（無料枠の範囲が望ましい）。

## 検討した選択肢

| 案 | 内容 | 判断 |
|---|---|---|
| ① ローカルだけ | 今のまま | 別の端末やスマホから使えない |
| **② 手元のマシン + Tailscale**（採用） | いつも起動しているマシンで動かし、Tailscale の tailnet の中だけで開けるようにする | 公開しないので認証を作らずに済む。データとキーも手元に残る。作業が少なく、費用もかからない |
| ③ クラウド（Cloud Run + Neon） | 認証は Cloud Run に直接付ける IAP、または Cloudflare Access、またはアプリに Google ログインを組み込む | マシンの電源に左右されない。ただし認証・シークレット管理・DB の移行・予算管理が必要。学ぶ題材としては有力なので、将来の選択肢として残す |

③の認証方式についての調べ（2026-10-31 時点）:

- **Cloudflare Access:** Cloud Run の `*.run.app` の URL から直接アクセスされると素通りされる。塞ぐには、アプリでのトークン検証かロードバランサーが必要で、さらに Cloudflare に置いたドメインも要る。
- **IAP（Cloud Run に直接付ける）:** ロードバランサーなし・追加料金なしで `run.app` の URL も保護できる。組織に属さない個人の Google Cloud プロジェクトでも、独自の OAuth クライアントを作れば使える。
- **アプリに Google ログインを組み込む:** 改修量は大きいが、クラウドに依存しない。ほかの人にも使ってもらうならこれになる。

## 決定

- **②を採用する。** オーナーのマシンで `./mvnw spring-boot:run -Papp` を実行し、`tailscale serve` で tailnet の中だけに HTTPS で公開する。手順は [docs/guides/tailscale.md](../guides/tailscale.md) にまとめた。
- Maven プロファイル `app` で frontend をビルドして jar に同梱し、Spring Boot が画面と API を同じオリジンから配る（`SpaConfig`）。
  - 画面の URL（`/plans/2026-11` など）は `index.html` を返す。
  - API のパスと、拡張子の付いた存在しないファイルは 404 のまま返す。間違った API の呼び出しが HTML になって返ってこないようにするため。
- backend は既定で `127.0.0.1` だけで待ち受ける（`RUNBUDDY_BIND_ADDRESS`）。ログイン機能がないので、同じ LAN の他人から開けないようにするため。`tailscale serve` はマシンの中から中継するので、これで届く。
- **`tailscale funnel`（インターネットへの公開）は使わない。**

## 結果（トレードオフ）

- 良い点: 認証を作らずに、スマホや別の端末から安全に使える。データも API キーも手元に残る。費用がかからない。
- 良い点: `app` プロファイル（画面と API を1つにまとめる）は、③に進むときもそのまま使える。
- 注意点: オーナーのマシンが起動していてネットワークにつながっている間しか使えない。
- 注意点: tailnet に入っている端末は、すべて「本人」として扱われる。tailnet をほかの人と共有するなら、先に認証が必要になる。
- 将来、ほかの人にも使ってもらう、いつでも使えるようにしたい、またはクラウドを学びたい、となったときは、③を新しい ADR で検討する。
