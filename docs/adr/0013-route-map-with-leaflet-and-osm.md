# ADR-0013: ランコースの地図は Leaflet と OpenStreetMap のタイルで描く

- ステータス: Accepted
- 日付: 2026-11-04
- 関連: #14、ADR-0012（軌跡の保存）、ADR-0010（手元のマシンで動かす）

## コンテキスト

日別詳細ページ（`/days/{日付}`）で、ランのコースを地図に線で描きたい。ADR-0012 で、軌跡（約 1,800 点）は FIT の原本から読めるようになった。残っているのは、地図ライブラリの選択と、位置情報の扱い（ADR-0012 §8 が #14 に残した判断）。

地図の背景（タイル）を読み込むと、見ている範囲、つまり自宅付近がタイルの配信元に伝わる。

## 決定

### 1. Leaflet + OpenStreetMap のラスタータイル

- `leaflet`（1.9）で描く。背景は `https://tile.openstreetmap.org/{z}/{x}/{y}.png`。キーもアカウントも要らない。
- 地図の右下に「© OpenStreetMap contributors」を出す（タイルの利用規約の条件）。
- 個人で1人が見る少量の利用なので、OpenStreetMap のタイル利用規約の範囲に収まる。利用が増える（公開する、複数人で使う）なら見直す。

### 2. 位置情報の扱い

- **スタート・ゴール付近は隠さない**（ADR-0012 §8 の方針を、地図でも続ける。オーナーの判断）。
- **タイルを読み込むのは、位置のあるランの地図を開いたときだけ。** 位置のないラン（トレッドミル・手入力・ダミー）は、地図を作らず「位置情報なし」と表示する。タイルの要求は出ない。
- 座標はブラウザにだけ送る。**AI 相談には送らない**（変更なし。`AdvisorTools` は軌跡を返さない）。
- 注意点として残す：地図を開くたびに、コース周辺のタイルの座標が OpenStreetMap に伝わる。気になるときは、案 C（背景なし）に切り替える。

### 3. 描画用に点を間引く

- `GET /api/runs/{activityId}/detail` に `route`（緯度・経度の配列）を足す。
- 間引きはドメインの `RunDetail.route(maxPoints)` に置く。均等に抜き、**スタートとゴールは必ず含める**。API は約 300 点を返す（各ラップの最初の点も残すので、ラップの数だけ増えうる。§5）。
- 心拍・標高・時刻は返さない。地図に要る分だけ渡す。`trackPoints`（元の点の数）は今まで通り返す。

### 4. コンポーネントは props だけ

- `RunRoute` は `route` だけを受け取る。データの取得は日別詳細ページのルートがする（ラップと同じ問い合わせを共用する）。
- 線とマークの色は、SVG の属性に `var(--...)` を書けないので、`className` を付けて `global.css` で DESIGN.md のトークンから決める（線は実績の色＝コーラル）。

### 5. ラップを選ぶと、地図でその区間を強調する

- ラップの表の行を押すと、地図上でそのラップの区間を濃く太い線で重ね、ほかのコースを薄くする。もう一度押すと元に戻る。
- **強調しても地図は動かさない。** 区間が見えていれば線を変えるだけにする。区間に寄せて、解除や次のラップでコース全体へ戻す作りにすると、ラップを順に押すたびに地図が拡大・縮小を繰り返して見づらかったため。手で拡大していて、区間が画面の外にあるときだけ、その区間へ移す。
- 各点がどのラップか（`route[].lap`）は backend が決める。ラップの開始時刻と軌跡の時刻は、FIT の同じ起点からの経過時間なので、`RunDetail.lapAt(offset)`（その時点までに始まった最後のラップ）で求まる。frontend は時刻の計算をしない。
- 間引き（`RunDetail.route`）は、**各ラップの最初の点を必ず残す**。均等に間引くだけだと、200 m のつなぎのような短いラップの点が消えて、強調する線が描けないため。点の数は「約 300」になる（ラップの数だけ増えうる）。
- 強調する区間は、前のラップの最後の点から始める（`lib/route.ts` の `lapSegment`）。線がコースから途切れて見えないようにするため。
- 選んでいるラップは `RunDetailPanel` が持つ唯一の状態。`RunRoute` と `RunLaps` は props だけで受け取る。位置のないランでは、ラップを選べない（ボタンを出さない）。

## 検討した選択肢

| 案 | 判断 |
|---|---|
| A. **Leaflet + OSM ラスタータイル**（採用） | 手軽で小さい。DESIGN.md の色には背景を合わせられない |
| B. MapLibre + OpenFreeMap | 背景の色を合わせられるが、依存が大きく、WebGL が要る。タイルの要求が外に出ることは A と同じ |
| C. 背景なし（SVG でコースだけ） | 外への通信がゼロで最も安全。ただし道や地名が見えず、コースの場所が分かりにくい |

## 結果（トレードオフ）

- 良い点：位置のあるランはコースが見える。依存は `leaflet` だけ。テストは jsdom で動く（地図は作れ、タイルは読まれない）。
- 良い点：間引きと「位置なし」はドメインと props のテストで守られる。
- 注意点：地図を開くたびに、見ている範囲が OpenStreetMap に伝わる（上の「位置情報の扱い」）。
- 注意点：スマホ幅では地図の高さを 240px にする。ページを横にはみ出さない。
- 将来の候補（範囲外）：ペースや心拍で線を色分けする。
